# Agent Note: 窄屏 viewport 保持会话区可用

Status: implemented

[English](2026-08-15-responsive-web-shell.md) | 中文

## 问题

Web 外壳会在宽度低于 1024px 时自动折叠侧边栏，但重新打开会拓宽侧边栏的网格轨道。这会压缩会话区，没有把会话列表当作临时导航。到了手机宽度，设置对话框仍把 188px 导航放在 800px 面板旁边，提供方行也坚持把所有操作放在同一行。于是最需要紧凑姿态的屏幕会裁切会话标题栏、设置内容、提供方名称或操作。

这些问题来自多个独立组件继续保留桌面几何信息。没有单一组件拥有手机布局，因此窄屏 viewport 得到的仍是一组各自合理、合起来却放不下的桌面宽度。

## 决策

在低于既有 1024px 自动折叠断点的 viewport 上，外壳继续以 56px 侧边栏控制栏作为网格轨道。打开侧边栏时，已存宽度会覆盖到会话区上方，并最多扩展到仍留出 48px 可见区域，同时在其后增加遮罩。点击遮罩、再次切换侧边栏或选择其他会话都会关闭浮层，但不会改变已存桌面宽度。

在 720px 及以下，设置面板变为占满 viewport 的纵向页面。分区导航变成可水平滚动的一行，内容使用余下高度。提供方行允许身份区和操作区换行；长名称以省略号收尾，不再拓宽页面。会话标题栏在同一断点使用更小间距和有宽度上限的面包屑。

这些断点仍是展示事实。布局 store 只记录既有桌面宽度偏好和瞬时窄屏浮层标记，不持久化从 viewport 推导出的几何信息。

## 备选方案

- **继续拓宽网格轨道。** 这能保留原有列求解器，但导航打开时会永久占用会话宽度，正是窄屏上的失败表现。
- **用全屏侧边栏替换紧凑控制栏。** 这给会话列表更多空间，却会移除始终可用的导航控件，并引入第二套手机外壳姿态。
- **只增加 CSS overflow 规则。** overflow 可以隐藏被裁切的内容，却无法保持会话轨道稳定，也无法在所选会话变化时关闭侧边栏。

## 影响

侧边栏打开时会暂时覆盖部分会话区，但会话区保持自身宽度和滚动位置。桌面几何信息、拖动宽度和详情栏让步链均保持不变。设置页面会使用完整手机 viewport，不再保留桌面对话框边距。

布局测试固定控制栏轨道、浮层宽度、关闭行为和保留的桌面宽度偏好。样式表测试固定 720px 设置纵向布局和提供方行换行，而装配后的无密钥 web snapshot 通过真实侧边栏控件证明构建后的插件图可以打开并关闭浮层。
