# Agent Note：远程根与 Cohub 插件边界

状态：提案

[English](2026-08-16-remote-roots-and-cohub-plugin-boundaries.md) | 中文

## 问题

云端工作区需要在 DSH 导航中可被发现，但不能伪装成本地 Workspace 目录。复用 Workspace 路径会错误地移动 Session cwd，并暗示 Shell 与文件系统处在同一远程执行环境。若把 Cohub 登录、文件、模型、生成资产和 Board 绑进一个插件，也会导致无身份依赖的界面无法复用。

## 决策

新增通用的客户端远程根注册服务。每个来源发布带明确标识的根，并使用 Provider 自有的不透明 ID 操作。契约没有本地路径，不创建或修改 DSH Workspace。浏览、读取和基于版本的比较后写入都位于来源边界之后。来源 ID 必须唯一，结构错误的快照明确失败，Cordis 卸载时撤销来源及其订阅。

Provider 快照与目录、读取、写入结果会在这层边界完成复制和深度冻结。返回的根与文件身份必须和请求一致，目录条目必须结构有效且 ID 唯一，写入结果只能是有效成功或明确的版本冲突。错误 Provider 数据会在进入显示状态前失败。

Cohub 不进入这个通用包。唯一的 Host 侧 Cohub Account 能力负责凭证和会话生命周期。独立的 Cohub 适配器通过通用能力接口提供 Space 文件、模型、生成和 Board。无身份依赖的文件树、文件、Board 和结果显示包只依赖这些通用接口。可选组合包只负责装配叶子插件，不能成为第二个状态所有者。

Workspace 浏览器只持有一个空 share 子 slot，用于把远程根放在本地行旁边。`@deepseek-ai/dsh-client-ui-remote-roots` 独立占用这个位置，观察通用注册服务，把每个带标识的远程根渲染成文件夹，并通过不透明 ID 按需读取子项。文件夹关闭时会取消请求，迟到结果不会生效，Provider 错误会原样显示并允许重试，插件卸载时整个界面注册都会撤销。本地 Session 搜索会隐藏远程树，不会声称自己能搜索远程内容。

## 影响

远程根可以呈现为文件夹，同时与 Workspace、cwd 和 Shell 保持语义分离。其他云端 Provider 能复用同一套界面。包和依赖边会增加，但每项能力可以独立加载和卸载。Board 与生成资产需要独立契约，不能借文件树传递。

## 未采用方案

没有把 `cohub://` 路径加入 Workspace，因为这会破坏现有 cwd 和执行环境语义。没有采用 iframe，因为这会让 Cohub 接管外围登录和界面生命周期。没有采用单体 Cohub 插件，因为通用界面会被登录依赖污染，叶子能力也无法独立卸载。

## 必需验证

实现版记录必须引用以下证据：重复来源拒绝、错误发布失败、不透明 ID 路由、明确的写入冲突、来源卸载撤销、卸载后的 Provider 更新无效、本地 Workspace 回归、匿名通用界面、身份失败，以及在隔离 Harness 数据目录中的真实 Cohub 组合流程。
