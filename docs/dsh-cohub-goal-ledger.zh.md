第一项实现决策是让远程根在结构上与本地 Workspace 分离。通用契约使用 Provider 自有的不透明根 ID 和节点 ID，并携带明确的云端、网络或外部标识。契约不包含本地路径、cwd、Shell、登录或 Cohub 名词。Cohub 只会是一个可独立卸载的来源。文件写入使用基于版本的比较后写入，版本冲突必须作为明确失败返回。

## 2026-08-16 · 通用远程根边界已实现

提交 `e1073dd47fc2eed887bfb5ad74e67c66f03cc99b` 新增 `@deepseek-ai/dsh-client-remote-roots`，并接入 Web 插件清单。该服务接收可独立卸载的来源，发布带明确标识的远程根，通过不透明 ID 路由目录、读取和写入操作，拒绝重复来源与重复根 ID，把版本冲突保留为显式结果，并在 Provider 发布错误结构时令聚合快照明确失败。卸载会撤销来源、订阅以及后续 Provider 更新的影响。六项专用验收测试通过。完成 Host 侧必需构建产物后，该包类型检查通过，客户端打包通过，完整 GUI 通道通过 272 个测试文件和 3,760 项测试；另有四项为原测试集已有的跳过。

完整 Web 构建也通过。Web 回放没有通过，因此不计入验收。在 Cohub 的 NFS 工作树上，源码启动的 Web 子进程进入 NFS 内核等待，并随着测试超时继续累积；确认现场后，只终止了该任务所属的进程组。把同一份已构建回放测试复制到本机临时盘后，NFS 等待消失，同时暴露了下一项环境事实：按安全边界使用 `--ignore-scripts` 安装依赖后，不存在 `node-pty` 原生二进制。无需该组件的六个文件、十四项测试通过，依赖共享启动层的产品场景则在运行前失败。没有为掩盖缺口而执行安装钩子或原生构建。自动研究记录将此标记为环境阻塞，不标记为保留，并把六项试验指标与零项基线分开保存。

现用工作树仍位于锁定提交的 `master`，原有 48 项无关状态保持不变。隔离分支只包含实现提交和未跟踪的自动研究审计文件。取证完成后，任务专属的临时验证副本与 Harness 数据目录已删除。

## 2026-08-16 · 匿名远程根文件树完成组合

Workspace 浏览器现在会在本地列表旁声明一个与供应方无关的子 slot。可独立加载的 `@deepseek-ai/dsh-client-ui-remote-roots` 包会填充它，不依赖账号或 Cohub。它会渲染 cloud/network/external 标识，通过不透明的来源、根和父级 ID 按需读取文件夹，显示加载状态和 Provider 错误，明确提供重试，在折叠或卸载时取消请求，并忽略迟到结果。本地 Session 搜索会隐藏该树，只搜索自身真实持有的行为。

真实 Slot 运行时组合同时挂载 Workspace 浏览器、远程根界面和注册服务。带云端标识的根能够出现并通过 Provider 回调展开，全程不会进入 Workspace 列表，Provider 注销后会消失。组件测试覆盖文件夹与文件渲染、精确 ID 和 AbortSignal 路由、失败后重试、取消与迟到结果、来源加载与错误变化。新包和受影响的 Workspace 包类型检查通过，新 bundle 构建成功，两个包的相关界面共 53 条定向测试通过。完整 GUI 通道也通过 276 个测试文件和 3,770 项测试，另有一项为既有跳过。仓库完整构建以退出码 0 通过。

依赖锁在离线且禁用安装脚本的条件下刷新。没有执行原生安装钩子、网络下载、运行配置安装、插件启用或主工作树写入。既有 Web replay 环境阻塞没有改变，也不计入本段证据。

## 2026-08-16 · Provider 返回边界完成收紧

远程根注册服务现在把所有 Provider 返回值都视为不可信运行数据。请求身份会在调用前校验，目录、读取和写入返回的身份必须与请求一致，重复或结构错误的目录条目会被拒绝，只接受有效文本结果和明确的版本冲突写入结果。发布的根、目录、文件与嵌套元数据都会完成复制和深度冻结，因此 Provider 后续修改原对象不会改变已经观察到的状态。

注册服务的 11 项专用测试通过，覆盖身份不匹配、无效标识和能力元数据、重复与无效条目、错误读写结果、明确冲突、复制与深度冻结。DSH-Cohub 组合校验共 24 项通过。定向格式检查、包类型检查和客户端打包也通过。

本段没有引入 Cohub 身份、令牌、本地路径、Workspace 修改、Shell 行为、运行配置安装或主工作树写入。

## 2026-08-16 · Host 侧唯一 Cohub Account 已建立

新的 MIT 包 `@deepseek-ai/dsh-cohub-account` 是 Cohub 设备登录、私有会话持久化、刷新与登出的唯一所有者。私有设备码和访问、刷新令牌不会进入公开快照。Cohub 适配器只能通过 `getAccessToken()` 取得令牌。实现使用平台 HTTP 接口，没有引入采用 Apache-2.0 的 Cohub CLI 或 SDK 依赖。

该服务会拒绝损坏的已存会话并保留现场，对并发刷新做单航班合并，在授权被明确拒绝时清除凭证，在临时刷新失败时保留已存会话，并在报告远端撤销警告前清理本地状态。代次隔离和生命周期取消会阻止迟到的登录、资料或刷新结果恢复已登出或卸载的账号。令牌交换成功后若资料请求临时失败，私有会话会留在内存中，重试不会再次使用一次性设备码。

10 项定向服务测试和 1 项真实 Loader 组合测试通过，外部 HTTP 全部使用模拟响应。Loader 测试通过测试专用 `cordis.yml` 登录，使用真实凭证 Provider 写入临时 Harness home，重启后恢复不含令牌的账号状态。Host 聚合类型检查、包打包、工作区约束、定向格式检查和 DSH-Cohub 组合校验 35 项均通过。

一次早期类型检查在新工作区入口接线前使用了 `pnpm exec`。Pnpm 更新了预期的锁文件入口，同时执行了仓库既有的 subprocess helper 与当前 worktree 专属 Lefthook 安装脚本。下载包数量为零，除预期锁文件入口外没有改变其他跟踪文件，也没有触碰现用 Profile 或主工作树。后续检查全部使用仓库已有二进制入口。这次执行越过了此前禁用安装脚本的纪律，已在这里如实记录，不作为验收证据。

没有使用真实 Cohub 凭证或请求真实端点，也没有启用、发布、推送或合并。
