## 2026-08-16 · Host 侧唯一 Cohub Account 已建立

新的 MIT 包 `@deepseek-ai/dsh-cohub-account` 是 Cohub 设备登录、私有会话持久化、刷新与登出的唯一所有者。私有设备码和访问、刷新令牌不会进入公开快照。Cohub 适配器只能通过 `getAccessToken()` 取得令牌。实现使用平台 HTTP 接口，没有引入采用 Apache-2.0 的 Cohub CLI 或 SDK 依赖。

该服务会拒绝损坏的已存会话并保留现场，对并发刷新做单航班合并，在授权被明确拒绝时清除凭证，在临时刷新失败时保留已存会话，并在报告远端撤销警告前清理本地状态。代次隔离和生命周期取消会阻止迟到的登录、资料或刷新结果恢复已登出或卸载的账号。令牌交换成功后若资料请求临时失败，私有会话会留在内存中，重试不会再次使用一次性设备码。

10 项定向服务测试和 1 项真实 Loader 组合测试通过，外部 HTTP 全部使用模拟响应。Loader 测试通过测试专用 `cordis.yml` 登录，使用真实凭证 Provider 写入临时 Harness home，重启后恢复不含令牌的账号状态。Host 聚合类型检查、包打包、工作区约束、定向格式检查和 DSH-Cohub 组合校验 35 项均通过。

一次早期类型检查在新工作区入口接线前使用了 `pnpm exec`。Pnpm 更新了预期的锁文件入口，同时执行了仓库既有的 subprocess helper 与当前 worktree 专属 Lefthook 安装脚本。下载包数量为零，除预期锁文件入口外没有改变其他跟踪文件，也没有触碰现用 Profile 或主工作树。后续检查全部使用仓库已有二进制入口。这次执行越过了此前禁用安装脚本的纪律，已在这里如实记录，不作为验收证据。

没有使用真实 Cohub 凭证或请求真实端点，也没有启用、发布、推送或合并。

## 2026-08-16 · Cohub Space 以带标识的云文件夹呈现

可独立卸载的 `@deepseek-ai/dsh-cohub-spaces` Host 适配器现已通过 Cohub 平台 HTTP API 列出账号可访问的 Space、浏览精确的 Space 相对目录、读取内联 UTF-8 文本，并以比较后写入的方式更新文本。它只从 `ctx.cohubAccount` 获取访问令牌，凭据不会越过类型化 Remote 边界。每一份响应都会经过校验。结构错误、准备中、二进制、无权限和传输故障都会明确暴露；写入版本过期时返回远端当前文本与版本，不会覆盖。

只在浏览器加载的 `@deepseek-ai/dsh-client-cohub-spaces` Provider 会把每个 Space 注册为带 `Cohub` 标识的文件夹形通用远端根目录。Provider 自有的不透明标识保留文件夹、文件与链接，不伪造本地路径。账号变化会刷新来源；代际隔离、取消处理和卸载清理会阻止迟到结果恢复已卸载状态。传输层故障会成为可见的 Provider 错误，不会伪装成空目录。

五条 Host 适配器测试、六条浏览器 Provider 测试和四条受影响的通用目录界面测试均通过。两个新包通过类型检查与定向静态检查，Host Remote 产物和浏览器包均成功生成，生成的浏览器产物不含凭据状态。没有引入本地 Workspace、cwd、Shell 目标、同步循环、删除/移动/上传操作、远端执行或 Work 发布。

## 2026-08-16 · Cohub 模型目录与原始补全适配器

可独立卸载的 `@deepseek-ai/dsh-llm-cohub` 包提供唯一的 DSH Provider 路由 `cohub`。它读取已登录账号可用的 Cohub 模型目录，用不会冲突的不透明 DSH 模型 ID 表示真实 Provider 与模型组合，并通过正式的 Space 级原始补全接口发送不含工具的请求。显式 `spaceId` 只负责 Cohub 的授权、归属、归档和计费，不会让该包依赖 Space/文件适配器或浏览器界面。

适配器只从 Cohub Account 服务获取 Bearer Token。模型目录、能力声明、图片附件、请求、流式事件、最终汇总、用量、失败、截断、取消和插件卸载都在边界处校验。计费接口没有调用方幂等键，因此不会自动重试。只有 DSH 的持久附件服务存在时，才启用可选用户图片。

Cohub 当前的原始补全契约不接收工具 Schema 或停止序列，也不保留工具调用历史。因此，DSH 请求包含工具、工具调用、工具结果、停止序列或 Assistant 图片时，会在网络请求前明确失败。没有用 Cohub Session 替代，因为那会把执行交给 Cohub Agent 运行时，破坏 DSH Provider 边界。

十项定向适配器测试通过。定向静态检查、包类型检查、包构建、Host 聚合类型检查、工作区约束、中英文 README 配对、模型体验与限制文档检查，以及 56 项 DSH-Cohub 组合校验全部通过。没有使用真实凭据或端点，也没有改 Cohub 代码、现用 Profile、主工作树，没有合并、推送、发布或发版。

## 2026-08-16 · 可恢复的 Cohub 多媒体生成工具

可独立卸载的 `@deepseek-ai/dsh-cohub-generation` 包现在提供三项 DSH 工具，分别负责读取已登录账号的 Cohub 多媒体模型目录、创建一项任务并等待、恢复查询已有任务。该包依赖 Cohub Account owner，不依赖 Space/文件、Board、浏览器界面、Cohub Session 或 Cohub Agent 执行。显式 Space 只提供 Cohub 授权、归属、归档和计费上下文。

计费创建请求不会重试。创建后若轮询失败、超时或取消，错误会保留任务 ID，状态工具可以恢复同一项任务，不会再次计费。模型目录、声明、任务状态、输出、价格元数据和计费结果都会校验。生成图片 URL 会保留；挂载 DSH 附件存储后，图片会在严格限制下下载并持久化，然后成为模型可见的图片块。下载失败会保留 URL，并给出明确警告。该版 DSH 没有持久视频或音频附件接口，因此它们保留为 Provider URL。内联 base64 视频或音频会携带可恢复任务 ID 明确失败。

首次测试发现了真实的模型目录解析错误，实现读取了声明对象而不是其中的 `content`，导致所有有效输入列表都被拒绝。该问题依据失败证据修正。现在九项定向测试通过，覆盖目录校验和隐藏、Space 级创建、轮询与计费、内联图片持久化、图片下载警告、轮询中断后不重复创建的恢复、失败和结构错误任务、402 拒绝以及卸载取消。定向静态检查、包与 Host 聚合类型检查、包构建、工作区约束、中英文文档检查和 65 项组合校验全部通过。

没有使用真实 Cohub 凭据或端点，也没有改 Cohub 代码、现用 Profile、主工作树，没有合并、推送、发布或发版。

## 2026-08-16 · 独立的 Cohub Board 只读界面

新的 `@deepseek-ai/dsh-cohub-board` Host 包只提供一项经过身份认证的 Board 只读检查。它通过 Cohub 正式 Board 接口只读取节点和连接，并校验请求对应的 Space 与 Board、有限且为正的几何数据、节点与连接 ID 唯一性、图引用、时间和 JSON 元数据；错误结构会被拒绝。Account 服务仍是 Bearer Token 的唯一所有者。创建、事务、校验、播放和发布方法都没有越过 Remote 边界。

可单独加载的 `@deepseek-ai/dsh-client-cohub-board` 包拥有自己的侧栏入口和浮层，不把 Board 行为塞进通用文件树。它通过现有 Space Remote 列出 Space 与文件夹，发现真实 `.board` 清单，独立校验清单，再把 Board 节点和连接显示在自适应画布上。公开 HTTP(S) 图片引用可以直接显示；由于没有把浏览器凭据或私有资源代理带进来，私有 Space 资源只显示为元数据卡片。该界面不会创建本地 Workspace，不改变 cwd，不启动 Cohub Session，不编辑文件，也不发布 Work。

五项 Host 测试和四项浏览器测试通过，覆盖只读 Remote 集、只在 Host 持有的授权信息、清单校验、错误结构与跨 Board 数据、悬空图引用、HTTP 错误、卸载取消、真实 slot 注册、清单发现、节点显示，以及坏清单的可见拒绝。两个包都通过类型检查并可独立构建，定向静态检查通过。

没有复制或修改 Cohub 代码。Cohub 仓库只作为接口事实来源读取。没有使用真实凭据或端点，也没有触碰现用 Profile、主工作树、合并、推送、发布或发版。
